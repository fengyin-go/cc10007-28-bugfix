# 数据分层建模工作台

离线版数仓分层建模工具，覆盖贴源层、明细层、汇总层、应用层的表结构设计、分区策略配置、质量规则编排与血缘关系管理，数据持久化到浏览器本地存储。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `data-layer-studio:entries` 这一项，或调用 `resetModule(模块)`。

## 快照恢复资格

快照策略只有同时满足以下条件才能「启用策略」，判定逻辑集中在
`frontend/src/data/recovery.ts`，快照、分区、存储治理读的是同一份结论：

- 最近一次恢复测试结论为「通过」；
- 恢复测试未过期（有效期按「恢复测试有效天数」计算，缺失时默认 30 天）；
- 保留份数为大于 0 的整数；
- 「目标表证据」与策略目标表一致。

补充规则：

- 测试失败或过期后，已启用的快照策略会自动退出保护资格并停用；引用了它的分区方案、
  存储治理策略也不能再启用，已启用的同样会被停用并给出原因。
- 重复提交同一「恢复测试回执号」只更新一次，不会覆盖当前结论；回执版本低于当前证据版本时
  拒绝写入，旧回执不能覆盖新版本。
- 启用动作会带上读取时的证据版本，若期间恢复测试已完成新版本，启用会返回版本冲突，
  并发操作只有确定的先后关系。
- 快照列表中的「恢复包」打开后可以看到最近一次测试、保留份数、目标表证据、有效期和逐条回执；
  列表与详情读取同一份数据，不会出现列表残留旧对象、详情值对不上的情况。
